# Ibex 最強化計画 v3 — 作業指示書

- 対象: [`ydah/ibex`](https://github.com/ydah/ibex)
- 対応設計: `ibex-world-strongest-design-v3.md`
- 宣言的設定基準: `ibex-declarative-configuration-policy.md`
- 対応監査: `ibex-world-strongest-adversarial-review.md`
- 原則: **active work、conditional experiment、research を明示的に分離する**
- 原則: **新しい grammar syntax は、programmatic semantics と evidence が固まるまで追加しない**

---

## 1. Priority model

| Label | Meaning |
|---|---|
| P0 | v1 release、truth boundary、既存契約の保護。最大8件 |
| P1 | v1後に現在の価値を強める |
| C | conditional。Decision Gate を通過した場合だけ実装 |
| R | research。release/roadmap completion を止めない |
| X | rejected/deferred。trigger が変わるまで着手しない |

P0 を増やす場合、既存 P0 を一つ落とす。

## 2. Universal work rules

## 2.1 Before implementation

必ず次を記録する。

```markdown
## Problem evidence

- user / grammar / fixture:
- current behavior:
- current workaround:
- why existing feature is insufficient:

## Semantics

- input:
- output:
- tie-break:
- errors:
- unsupported:
- action execution:
- source mapping:

## Boundary impact

- compatible mode:
- Grammar IR:
- Automaton IR:
- table ABI:
- runtime gem:
- generated bytes:
- schema:
- path/network:

## Oracle

- independent reference:
- property:
- fault injection:
- bounded status:

## Kill conditions

- ...
```

問題 evidence がない場合、task は `Research` へ落とす。

## 2.2 Grammar syntax budget

新しい keyword/declaration/operatorを追加する前に:

1. internal/programmatic API
2. executable semantics tests
3. two representative grammars
4. formatter/LSP design
5. compatibility and migration note
6. syntax proposal
7. only then self-hosted grammar change

syntax から先に作らない。

## 2.3 Declarative configuration admission

CLI option または runtime/build setting に grammar syntax を追加する PR は、
`ibex-declarative-configuration-policy.md` の Admission Test を添付する。

必須表:

```markdown
## Configuration admission

- canonical key:
- domain effect:
- owner: grammar-contract / grammar-minimum / project-build / invocation
- persistence:
- static validation:
- scope/composition:
- IR representation:
- manifest representation:
- override algebra:
- rejected alternatives:
```

次に該当するものは grammar syntax を作らない。

- operation/subcommand selection
- output path
- report/presentation
- analysis budget
- packaging/deployment
- environment/secret
- global diagnostic suppression

generic `cli_option`、untyped key-value、environment conditional は禁止する。

## 2.4 Trust labels

各 command/API を次のいずれかで明記する。

- `static-no-user-code`
- `syntax-no-parser-actions`
- `executes-lexer-actions`
- `executes-application-code`
- `unsafe-opt-in`

`syntax-only` を `no user code` の同義語にしない。

## 2.5 ABI impact assessment

runtime-facing PR は次を必須記載する。

```markdown
## ABI assessment

- current table format:
- new fields/constants:
- old runtime + new parser:
- new runtime + old parser:
- embedded runtime:
- regeneration required:
- version bump:
- feature-off bytes:
```

## 2.6 Tests

機能に応じて選ぶ。すべてを一つの matrix に入れない。

- characterization
- unit
- property
- small exhaustive oracle
- black-box differential
- fault injection
- schema invalid fixtures
- generated-source golden
- feature interaction matrix
- scheduled fuzz
- external human review

## 2.7 Legal/provenance

- external source/grammar revision と license を記録
- GPL implementation を MIT codebase へ翻訳しない
- algorithm は paper/specification と独立設計から実装
- Unicode database の source/version/license を記録
- third-party grammar 本体を必要なく commit しない

## S001 — Prototype a generated-language syntax session API

**Priority:** P1
**Depends on:** B001, H001

### Goal

generic LSPではなく、existing Red/Green CSTを使う syntax service boundaryを作る。

### Initial scope

- open source
- apply edits
- syntax root
- diagnostics
- expected tokens at parser failure
- reuse/fallback metrics
- cancellation/resource limits

### Trust API

Expose the class/artifact profile rather than pretending a session-time flag can sandbox already loaded Ruby:

```ruby
parser.syntax_execution_profile # :trusted_application_code or :declarative
parser.syntax_session(source)
```

- `:trusted_application_code`: existing class load/user sections/lexer actions are application-trusted
- `:declarative`: separately generated action-free syntax artifact and declarative lexer

No safe default that silently executes arbitrary lexer actions。

### Packaging decision

Evaluate:

- `ibex-runtime`
- generator gem
- separate `ibex-workbench`

Do not add LSP protocol in this task.

### Done

- parser actions do not run
- lexer-action behavior explicit
- current CST invariants retained
- random edit equivalence
- no workspace semantics claim

# 8. Completion definition

The active plan is complete when:

- v1.0 evidence is complete
- current Preview/Experimental surface has explicit decisions
- migration and workload evidence cover the primary users
- trust boundaries are accurate
- runtime/table ABI evolution is documented
- every CLI option has a declared owner class
- canonical parser contract values can be declared in grammar
- effective configuration and origin are inspectable
- grammar/CLI conflicts cannot silently change canonical generation
- generated table artifacts can be independently checked without loading application code
- syntax services reuse the existing CST and expose lexer-action trust honestly
- conditional experiments have GO/NO-GO outcomes

The plan is **not** incomplete merely because GLR、portable runtime、custom package management、
query DSL、formatter DSL are absent. Those are separate product decisions, not prerequisites for Ibex to be a world-class tool.
