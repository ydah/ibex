# Investigation: Stage A safety net

## Existing facilities

- `test/property/pipeline_invariants_test.rb` already exercises fixed-seed
  grammars across the four algorithms and checks direct/reference and
  plain/compact equality.
- IR golden fixtures already cover validated v1/v2 round trips.
- generated parser integration tests cover CST, semantic locations, multiple
  entries, resource limits, and deterministic code generation independently.
- `examples/` provides self-authored grammars and `rake grammar:test` provides
  a production-coverage gate.
- `Ibex::Samples` already provides deterministic bounded sentence generation,
  exact minimum terminal costs, and non-recursive expansion. It is the Stage A
  generator; only coverage-oriented selection and differential execution are
  missing.
- benchmark v2 already separates deterministic gates from observational
  timing and memory values.

The missing layer is orchestration: the axes are not declared in data, golden
generation is not one reviewable workflow, the examples do not carry gallery
provenance/corpora, and adversarial cases are not available under one task.

## Affected code

| Area | Current responsibility | Change |
|---|---|---|
| `test/property/` | fixed-seed implementation properties | retain as an independent oracle |
| `test/support/` | reusable property harnesses | add a matrix runner |
| `tool/quality/` | repository quality scripts | add golden and gallery runners |
| `Rakefile` | public development entry points | add Stage A tasks |
| `.github/workflows/main.yml` | CI gates | run short PR gates and scheduled full gates |
| `examples/` | small public examples | leave unchanged |
| `gallery/` | absent | add three self-authored, licensed fixtures |

## Contracts that must remain unchanged

- all core IR schemas remain closed and unchanged;
- generated bytes only change through an explicit golden update;
- wall-clock and RSS observations remain non-gating;
- analysis does not evaluate user semantic actions;
- every generated or searched case has explicit limits.

## Choices

| Choice | Benefit | Cost | Decision |
|---|---|---|---|
| replace property tests with the matrix | less duplication | loses an independent fixed-seed oracle | reject |
| encode combinations in Ruby | simple initially | adding an axis requires code changes | reject |
| declare axes in YAML and keep assertions in a runner | reviewable combinations, focused code | one support abstraction | use |
| treat `examples/` as the gallery | no copied grammar | cannot attach per-grammar corpus and provenance cleanly | reject |
| add three small self-authored gallery grammars | explicit license and bounded CI | limited language breadth | use |

## Resolved questions

- The `locations` matrix axis means whether generated semantic actions consume
  token locations; it is not a new grammar pragma.
- The `isolated` entries value is valid only for a multiple-entry grammar. The
  runner maps it to `entry_isolation: true`.
- Golden bytes use generated source files plus a digest index. A mismatch
  reports the first byte offset; the source file remains available for a
  normal version-control diff.
- Stage A does not introduce a DFA or a regular-expression timeout policy.
  Existing generated-lexer validation and bounded runtime tests remain the
  applicable pre-v1 contract.
