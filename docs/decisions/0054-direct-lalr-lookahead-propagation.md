# 0054: Build LALR lookaheads directly over LR(0) states

- Status: Accepted
- Date: 2026-07-25
- Supersedes: ADR 0008's canonical-and-merge implementation

## Context

The original builder constructed every canonical LR(1) state and merged equal
LR(0) cores for both LALR and SLR. That was a small, auditable foundation, but
the versioned representative benchmark retained 1,294 intermediate states to
emit 250 final LALR states. The replacement must preserve state numbering, item
lookaheads, conflict details, default reductions, serialized Automaton IR, and
every downstream generated byte.

## Decision

LALR and SLR now construct the deterministic LR(0) collection first. A DeRemer-family propagation graph has one node for each
LR(0) item occurrence. Shifted items propagate their lookahead set across the corresponding DFA transition. For an item with a
nonterminal after the dot, `FIRST` of the suffix contributes spontaneous terminals to that nonterminal's initial items; a
nullable suffix adds propagation edges from the source item. EOF seeds the augmented start item. A deterministic worklist
computes the least fixed point without materializing a canonical LR(1) collection.

SLR uses the same LR(0) collection and replaces completed-item lookaheads with the existing FOLLOW sets. Canonical `lr1` retains
the original canonical collection. All strategies continue through the same action candidate, conflict resolver, default
reduction, counterexample, table, and code-generation paths.

`LALR::Builder` defaults to `lalr_strategy: :direct`. The explicit `:canonical_merge` reference strategy remains available for
equivalence tests, benchmark-v1 reproduction, and rollback; unknown strategies fail before construction. It is not exposed as a
grammar or Automaton IR option because both implementations have the same `lalr1` language contract.

`BuildMetrics` records `construction_states`, optional `canonical_states`, `final_states`, and the strategy. Direct LALR does not
claim a canonical count it never constructs. Benchmark schema v2 therefore records `construction_strategy` and
`construction_intermediate_states`; schema-v1 history remains immutable and is reproduced with the reference strategy.

The representative grammar retains 250 construction states instead of 1,294 canonical states, a reduction of 1,044 (80.7%).
The default and reference builders must serialize byte-identical Grammar and Automaton IR for the representative grammar, every
shipped example, conflict fixtures, and fixed-seed generated grammars. Plain/compact tables, generated sources, runtime results,
conflict resolution, default reductions, SLR, and canonical LR(1) remain downstream invariants.

## Consequences

- Default LALR and SLR construction no longer retain canonical LR(1) state explosions.
- State ids, diagnostics, Automaton IR, tables, and generated Ruby remain compatible.
- The reference path makes algorithm regressions directly testable and keeps old benchmark artifacts reproducible at their
  measured revision.
- The propagation graph uses LR(0) item occurrences rather than exposing lookahead relations in Automaton IR.
- IELR may now begin from a stable direct-LALR baseline, but requires a separate algorithm and IR-label decision.
