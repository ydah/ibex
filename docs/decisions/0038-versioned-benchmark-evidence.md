# ADR 0038: Use versioned benchmark artifacts as optimization evidence

- Status: Accepted
- Date: 2026-07-25
- Supersedes: the Direct LALR entry boundary in ADR 0024 and the benchmark prerequisite for chain elimination and generated
  `case` dispatch in ADR 0035

## Context

The previous optimization boundaries required a representative grammar and repeatable measurements, but the repository had only
small examples and an unversioned generated chain. Results lacked a schema, environment identity, canonical intermediate state
count, memory observation, comparable table representations, and committed history. That made an optimization decision difficult
to reproduce and encouraged treating noisy wall-clock values as CI thresholds.

## Decision

Ibex owns `benchmark/grammars/representative.y` and its input. The grammar intentionally exercises a broad deterministic language
surface without third-party source or license obligations. `benchmark/pipeline.rb` emits an `ibex_benchmark` document with
`schema_version: 1`; `schema/benchmark-v1.schema.json` is the public artifact contract. Results under `benchmark/results/v1/`
form an append-only, environment-named history.

Each document includes full environment metadata, generation and stage observations, peak RSS where the host exposes it, runtime
observations for plain and compact tables, canonical and final states, production count, table cells and deterministic bytes,
generated bytes, and SHA-256 digests. Timing and RSS are observational and never CI thresholds. Fixed-seed structure and digests
are reproduced in CI.

Scheduled and manually dispatched full runs write
`ibex-benchmark-<full-revision>-ruby-<version>-<runner-os>-<runner-arch>.json` and retain the workflow artifact for 30 days. The
workflow artifact name uses only the numeric run id and attempt. A result enters the repository only after a reviewer checks out
the measured revision, runs `benchmark/verify.rb` against the downloaded file, and inspects the observations. Accepted files use
`YYYY-MM-DD-<revision12>-ruby-<version>-<ruby-platform>.json` under `benchmark/results/v1/`; existing files are never replaced or
removed. The initial environment-only baseline predates this ingestion rule and is retained unchanged as the starting observation.

Timing or RSS comparisons are valid only when the complete `environment` and `configuration` objects match. A change in Ruby,
Ibex, OS, CPU, processor count, grammar, input, seed, or iteration policy starts a distinct series. Structure and digest
verification remains portable and is performed even when environments differ.

The first baseline has 139 productions, 1,294 canonical intermediate states, and 250 final LALR states. On its recorded arm64
MRI environment, canonical construction dominates generation. The 5.18-to-1 intermediate/final state ratio and the committed
stage observation satisfy ADR 0024's evidence requirement: a Direct LALR implementation phase may begin. It must still prove,
against the current canonical-and-merge builder:

1. byte-identical Grammar and Automaton IR for the representative grammar, all examples, fixed-seed generated grammars, and
   conflict fixtures;
2. no regression in SLR, LR(1), conflict resolution, counterexamples, or default reductions;
3. lower intermediate-state retention or a repeatable construction-time/RSS improvement on at least two supported MRI versions;
4. fallback or rejection behavior for unsupported relation cases; and
5. updated algorithm documentation without exposing relation internals in Automaton IR.

[ADR 0054](0054-direct-lalr-lookahead-propagation.md) satisfies these conditions with direct LR(0)-item lookahead propagation,
an explicit canonical-merge reference path, byte-equivalence fixtures, and benchmark schema v2 construction metrics.

The same artifact is the required baseline for chain-rule elimination and generated `case` dispatch experiments, but does not
authorize either as a default. A candidate must be measured in at least five isolated runs on one named environment and reproduced
on a second supported MRI version. It qualifies only with either a median runtime improvement of at least 5% or a generated/table
size reduction of at least 10%, without a regression of 5% or more in the other recorded dimension. Candidate artifacts must keep
runtime-result and parser-behavior digests equal. A follow-up ADR must define source-map behavior, debugger/tracer identity,
table-format compatibility, and rollback before adoption.

[ADR 0058](0058-reject-chain-elimination-and-case-dispatch.md) applies this gate. Five-process measurements on MRI 3.4.9 and
4.0.0 show a 15.494% and 16.489% runtime improvement for compatible per-state case lookup, but a 198.170% generated-size
regression, so the candidate is rejected. Chain elimination is also rejected because production identities are observable across
hooks, tracing, coverage, debugging, and source maps.

This decision also satisfies the representative benchmark and committed-history prerequisite in ADR 0024. Pages/YARD repository
permissions and publication ownership remain separate.

## Consequences

- Direct LALR now has an evidence-backed implementation entry point rather than an open-ended deferral.
- Chain elimination and generated `case` dispatch have quantitative candidate gates, while noisy observations remain out of CI
  pass/fail policy.
- Structural changes require an intentional baseline and digest update; performance changes create a new environment-named result
  rather than rewriting prior history.
- Full workflow observations survive beyond job logs long enough for review, while unreviewed artifacts expire automatically.
- `Builder#metrics` is a frozen two-count diagnostic API. It remains outside Automaton IR and parser runtime contracts.
